핵심 구성

서버·클라이언트·배포 자동화까지 4가지 축으로 정리했습니다.

서버 (API + PostgreSQL)

Docker Compose로 DB·API 서버를 한 번에 실행합니다. LDAP 연동, 거래처 MSSQL 조직 동기화 등 선택 기능을 지원합니다.

클라이언트 빌드·배포

macOS(.dmg)/Windows(.exe) 설치 파일을 빌드해 GitHub Releases로 배포합니다. 설치된 앱은 electron-updater로 자동 업데이트됩니다.

배포 자동화

Self-hosted GitHub Actions Runner로 main 브랜치 push 시 서버 PC의 Docker가 자동 갱신됩니다. 서버 IP를 GitHub에 알릴 필요가 없습니다.

거래처(파트너) 배포

앱 이름·ID·기본 API 주소를 거래처용으로 분리 설정하고, MSSQL 조직 동기화·Synology LDAP 연동을 켤 수 있습니다.

빠른 시작

DB만 Docker로 띄우고 서버는 로컬에서 실행하는 개발 환경 기준입니다.

1
docker compose up -d db 로 PostgreSQL을 띄우세요. (호스트 포트 5433)
2
packages/server에 .env를 두고 DATABASE_URL, JWT_SECRET을 설정하세요.
3
npm run db:push로 스키마를 반영한 뒤 npm run dev로 서버를 실행하세요.
4
클라이언트는 npm run build:app(전체) 또는 build:app:mac / build:app:win으로 빌드합니다.
macOS에서 "손상되었기 때문에 열 수 없습니다" 경고가 뜰 때
아직 앱 서명이 적용되지 않아 나타나는 정상적인 경고입니다. 사용자에게 xattr -cr /Applications/앱이름.app 안내가 필요합니다. 근본 해결은 Apple Developer 계정으로 코드사인·공증이 필요합니다(현재 보류).

자주 발생하는 문제

더 자세한 점검 절차는 전체 가이드의 트러블슈팅 항목을 참고하세요.

배포 후 웹/앱에서 흰 화면만 보여요.+

/debug-client로 클라이언트 파일이 서버 이미지에 포함됐는지 먼저 확인하고, /health로 API 서버 자체가 정상인지 확인하세요.

채팅 목록이 "목록을 불러올 수 없습니다"라고 나와요.+

PostgreSQL이 떠 있지 않거나 DATABASE_URL이 잘못된 경우입니다. docker compose ps로 db 컨테이너 상태를 확인하세요.

자동 업데이트가 동작하지 않아요.+

GitHub Releases에 latest.yml/latest-mac.yml이 함께 첨부됐는지 확인하세요. 비공개 저장소는 404가 나서 Generic 업데이트 서버 방식이 필요합니다.

git pull만 했는데 DB에 변경사항이 반영 안 돼요.+

정상입니다. git pull은 코드만 갱신합니다. 서버 PC에서 npm run db:push 또는 npm run db:migrate:deploy를 한 번 더 실행해야 합니다.
